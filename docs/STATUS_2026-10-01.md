## Known issue found in review (fixed in 1.3.1)

Station-scoped service messages are matched by station **name**. PIDS use MTR's station name (`client/live/BoardBuilder.java:63`), but the terminal (`client/wayfinding/PassengerTerminalScreen.java:154-171`) and the station information board (`client/wayfinding/WayfindingSignRenderer.java:154`) use the *resolved* name, in which a manual name override wins. A terminal or board with a manual name therefore loses that station's messages while the PIDS beside it shows them. **Confirmed live 2026-10-01 (B10):** a terminal named "Alpha Central" showed only the network message; "Alpha severe test" was missing while its departures still came from MTR's Alpha. Proposed fix (not one line, so left for 1.3.1): look messages up by the MTR station name when the block resolves an MTR station, and fall back to the manual name only when it does not. **Fixed in 1.3.1** exactly so (`ServiceMessages.messageStation`, `ResolvedWayfinding.mtrStationName`; tests in `ServiceMessagesTest`, `WayfindingResolverTest`). Re-checked in game 2026-10-01: terminal and info board named "Alpha Central" show "!! Alpha severe test" and the network message.

## Requests raised during the 1.3 check (not for 1.3)

- **Automatic boarding step / gap filler** (2026-10-01): a platform-edge piece that extends a step toward the train when one is stopping, keyed to the arriving train, for step-free boarding. New feature, so out of scope for 1.3 under the no-new-features rule; candidate for 1.4. Needs design against the performance contract (no per-tick block entity work, no new server polling) before any code.
- **Platform screen doors for curved platforms** (2026-10-01): PSD/APG pieces that follow the 45°/convex/concave edges. MTR's own PSDs are straight only. New blocks, so out of scope for 1.3; 1.4 candidate. Constraint: MTR opens doors for an *unlocked MTR PSD/APG door* or a `PlatformHelper` block (`docs/MTR_INTEGRATION.md`), and ATA must stay mixin-free, so the design has to work with MTR's door check as it is, not change it.
- **Concourse board, London St Pancras / TfL style** (2026-10-01): an explicit "Platform" column heading, a departures/arrivals choice, and a station summary (number of platforms, your arriving platform). Today the concourse board already shows each row's MTR platform name (`client/live/BoardBuilder.java:116-121`, `:169-170`) and can be limited to chosen platforms in manual mode, but has no heading, arrivals view or summary. 1.4 candidate.
- **Platform-integrated drop-down screen doors** (2026-10-01): a combined platform-edge block and platform screen door whose barrier lowers into the block itself when a train is in, like vertical-lift platform barriers used in Japan. Same constraints as the curved PSD entry (MTR's door check as is, no mixins); 1.4 candidate, together with curved PSDs.

## Bugs found during the 1.3 check

- **Station picker: search box overlaps "Found: …" in Automatic mode** (2026-10-01, screenshot). `client/live/LiveConfigScreen.java:85` adds the filter field at `y + 24` and keeps it visible and focusable in Automatic mode, while `:207` draws "Found: …" at `y + 28` on top of it; typing shows both texts ghosted together. The field only filters the manual list, so in Automatic mode it does nothing. Same screen base for every live display (PIDS, CIS, concourse) and the speaker. **Fixed** (approved by the release owner): the field is hidden in Automatic mode (`filterField.visible = mode == MANUAL` in `refreshLists()`).
- **Manual station list always empty** (2026-10-01, found because B4 showed no stations). `client/live/MtrStationDataProvider.listStations` started with `stationListAt = Long.MIN_VALUE` and refreshed when `now - stationListAt > RESOLVE_MILLIS`; `now - Long.MIN_VALUE` overflows to a negative number, so the list was never built and stayed `List.of()`. Every manual picker (live displays, speakers, terminals, kiosks, e-paper boards, signs) showed no stations, and a manual name could not be looked up by station name (`WayfindingEditScreen.java:307`). **Fixed** (one line, obviously safe): refresh also when `stationListAt == Long.MIN_VALUE`. Not covered by a unit test (the method reads MTR client data). Re-test: B4–B6.

## MTR limit found during the 1.3 check

- **Manual picker only lists stations MTR has sent to the client** (2026-10-01, B4/B6). Standing on Alpha P1 (x≈16), the list showed Alpha (area to x 70) and Beta (x 94–197) but not Gamma (x 227–338). ATA lists `MinecraftClientData.getInstance().stations`, and MTR 4.0.5 only syncs data near the player; MTR has no setting for that range. Not an ATA bug and not fixable without changing MTR. Open: what a block manually set to a far station shows once that station leaves the client's data (B6).
- **E-paper text too large on 1–2 wide boards** (2026-10-01, screenshot): row text is a fixed size (`client/wayfinding/EPaperLayout.java:30-31`, `HEADER_SCALE 0.5`, `ROW_SCALE 0.4`) whatever the board width, so on a 1-wide board route and destination truncate to "R…" / "Al…". Not a data bug. Proposed for 1.3.1: scale row text with panel width (or a smaller minimum), checked by eye on 1-, 2- and 3-wide boards. Not changed in 1.3 (visual change that needs live review).
- **"Alpha" as destination on Alpha's boards** (2026-10-01): not a bug. Routes were edited at 15:28 to Gamma → Beta → Alpha; MTR's own map API (`localhost:8888/mtr/api/map/stations-and-routes`) confirms, and ATA shows MTR's destination unchanged (`MtrStationDataProvider.java:249`).
- **Station information board editor: street box drawn over the platform box** (2026-10-01, screenshot). `client/wayfinding/WayfindingEditScreen.java:227` placed the street field at `left` with full width on the same row as the platform field (the `BOARD` panel has both). **Fixed** (one line): street field starts after the platform/exit columns, as the destination field beside it already did. Build 3142a22b, 194 tests green; checked in game 2026-10-01: Platform and Street boxes side by side, no overlap. Also noted, not changed: the `BOARD` panel enables a destination field that is never shown, because the street field takes the `else if` (`:226-229`).
- **Trackside fence flickering (z-fighting)** (2026-10-01, tester: "glitches whenever you look at it"). The trackside post ran to y=16 under a cap whose top is also y=16, and the top rail ran 0.5 px into the cap, so same-facing faces with different textures shared a plane. Confirmed in game (rail/post steel drawn through the dark cap). **Fixed** in `tools/assets_elevated.py` (post to y=15, rail to z=6.5); tester confirmed the flicker is gone.
- **Same defect in other models**, found with the new `tools/check_zfighting.py` (flags same-plane, same-facing, different-texture faces not covered by another element): viaduct girder/stringer/platform-support beams (both materials), platform wind screen (both), bus stop sign (flag in the pole's plane), catenary cantilever and insulator. **Fixed** by shortening or nudging one element each; checker now reports 0 models. Build 3112a40d, 194 tests, asset audit green. These were not individually re-checked by eye.
